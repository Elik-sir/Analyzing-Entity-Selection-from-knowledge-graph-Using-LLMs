# Experimental protocol

This document describes the current implementation. The article archive retains the original frozen inputs and observed outcomes. Replaying those inputs and constructing new data are distinct operations.

## Tasks and populations

The selection target contains the starting entity, requested endpoints, and intermediate entities on all supporting routes. This measures route coverage; it does not assert that every card is indispensable evidence.

`graph_motives/preparation/registry.py` defines the motif grid: chain 3?6; star-in/star-out 3?10; tree-in/tree-out 5?10; rhombus 4; hourglass 5. Main pools have 25 candidates total. Core has 100 questions per motif at sizes 6, 6, 6, 6, 6, 4, and 5. Calibration uses separate microtasks.

Pair conditions using task/base IDs, preserving graph, question semantics, candidate pool, and references where required. Join noise variants by identity, not row position. Preserve planned counts and report shortages.

## Evidence and identity

The registry defines names, evidence, noise, placement, and question style. Contrasts include representation (K1/K5, K7/K8), question (K1/K7, K5/K8), adjacency (K1/K2, K5/K6), placement (K1/K3/K4), real names/pseudonyms (R1-matched/K1, R2-matched/K2), names/types (R0/K0), and text/keys (K5/K5k).

Controlled evidence retains all typed directed relations induced by the candidate pool, including distractor relations. Never filter facts by reference membership. Explicit, text, and key formats encode designated graph facts. Question semantics and the witness oracle are in `preparation/questions.py`.

R0/K0 show names/types without relations. Their prompt permits prior name knowledge while requiring abstention when connections cannot be established. Other controlled prompts restrict evidence to the supplied input.

The current pseudonym builder uses deterministic, collision-checked `pronounceable_alias_v2` names. Existing archived aliases are frozen input and are not regenerated by a model plan. Changes to alias generation or tokenization define a new configuration.

Native Braw preserves metadata; Braw+E adds explicit relations. Their difference from controlled tasks may involve metadata, question, and protocol. A private graph route does not certify sufficient native textual evidence.

## Public/private boundary

Solver messages include permitted questions, candidates, evidence, and observations. Private graph IDs, references, gold membership, and audit findings must not enter solver input. References are available for local scoring and an explicitly configured judge.

Incremental selection initially shows names/types. Choosing an entity reveals its permitted facts by the same rule for all candidates; unselected facts stay hidden. Episodes allow up to 26 turns by default.

Legacy tasks retain required selection/answer/judge serialization in `legacy_protocol.py` and use the common runner. Answering uses newly selected cards. Correctness remains unknown without a judge. Selection accuracy does not substitute for answer evaluation.

## Execution and metrics

The runner fixes temperature at zero and freezes configuration, caps, inputs, model settings, code hashes, and package versions. Changes require a new run. Invalid output is not repaired by another model call. Only HTTP 429 is automatically retried; unknown dispatch outcomes remain recorded.

Primary precision/recall/F1 sum valid individual scores and divide by planned N. Invalid/pending outcomes contribute zero and retain null individual scores. Exact is valid exact matches divided by planned N. Unknown selected names reduce precision. Legacy applies whitespace/case normalization; controlled selection uses exact names.

The shared report records hashes, filters, counts, and denominator policy and reproduces primary aggregates. Inferential claims require a specified analysis of pairing, repeated tasks/entities, sampling, and multiple comparisons; generic plots alone do not provide this.

## Interpretation and missing evidence

Controlled text is templated from graph facts. Comparing it with triples tests representation, not arbitrary implicit reasoning in prose. Name masking changes tokenization and cannot be interpreted as a pure memory manipulation. Native/controlled comparisons may change multiple factors.

Metrics-only Gemma records cannot supply missing raw replies. Archived incremental inputs do not recover missing turns. Unknown provider metadata stays unknown. Missing/invalid outcomes retain their statuses and denominators.
